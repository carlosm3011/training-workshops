# Lab 1 - Establishing Basic BGP Connectivity

## Objectives
- Configure a basic eBGP session between two routers.
- Verify the BGP Finite State Machine (FSM) transitions.
- Originate and verify a prefix announcement.
- Inspect BGP Path Attributes (AS_PATH, NEXT_HOP).

## Topology
We will use a simple point-to-point topology:
- **Router A (AS 65001)**
  - Interface IP: 10.0.0.1/30
  - Loopback: 1.1.1.1/32
- **Router B (AS 65002)**
  - Interface IP: 10.0.0.2/30
  - Loopback: 2.2.2.2/32

---

Use the provided `lab-1.clab.yml` to start the topology:


## Step 1: Connectivity Check
Before BGP can establish a session, the underlying IP connectivity must be functional.

```text
Router-A# ping 10.0.0.2
Type escape sequence to abort.
Sending 5, 100-byte ICMP Echos to 10.0.0.2, timeout is 2 seconds:
!!!!!
Success rate is 100 percent (5/5)
```

## Step 2: BGP Configuration
Configure the BGP process and the neighbor relationship.

### Router A
```text
router bgp 65001
 neighbor 10.0.0.2 remote-as 65002
 network 1.1.1.1 mask 255.255.255.255
```

### Router B
```text
router bgp 65002
 neighbor 10.0.0.1 remote-as 65001
 network 2.2.2.2 mask 255.255.255.255
```

## Step 3: Verifying the Session
Observe the BGP state. It should move from `Active` or `OpenSent` to `Established`.

```text
Router-A# show ip bgp summary
BGP router identifier 1.1.1.1, local AS number 65001
...
Neighbor        V           AS MsgRcvd MsgSent   TblVer  InQ OutQ Up/Down  State/PfxRcd
10.0.0.2        4        65002      10      10        3    0    0 00:05:21        1
```

## Step 4: Inspecting Attributes
Check how the prefixes appear in the BGP table and note the attributes discussed in Module 03.

```text
Router-A# show ip bgp
BGP table version is 3, local router ID is 1.1.1.1
Status codes: s suppressed, d damped, h history, * valid, > best, i - internal, 
              r RIB-failure, S Stale, m multipath, b backup-path, f RT-Filter, 
              x best-external, a additional-path, c RIB-compressed, 
Origin codes: i - IGP, e - EGP, ? - incomplete

   Network          Next Hop            Metric LocPrf Weight Path
*> 1.1.1.1/32       0.0.0.0                  0         32768 i
*> 2.2.2.2/32       10.0.0.2                 0             0 65002 i
```

**Observations:**
- **AS_PATH:** Notice the `Path` attribute for `2.2.2.2/32` shows `65002`.
- **NEXT_HOP:** The `Next Hop` for the remote prefix is the interface IP of Router B.
- **ORIGIN:** The `i` at the end indicates the route was originated via an IGP (the `network` command).

## Summary
In this lab, you successfully established an eBGP session and exchanged routes. You observed the fundamental attributes that BGP uses to track the origin and path of a prefix.
